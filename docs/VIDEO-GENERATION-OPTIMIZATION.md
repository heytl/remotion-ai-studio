# 视频生成效果优化记录

完成日期：2026-08-17  
Schema 版本：v2

## 1. 优化目标与基线问题

本轮针对以下实际成片问题进行完整重构：

- 旁白整段作为字幕常驻，阅读负担大。
- 底部字幕覆盖图文标题和正文。
- AI 虽然生成了 `visual` 描述，但渲染阶段没有使用。
- `imageText` 未配置图片时只剩纯色背景和标题，留白过多。
- 每个场景只有一次约 0.7 秒的整页入场，之后长时间静止。
- 要点在场景开头约 1 秒内全部出现，和旁白语义不同步。
- 场景时长只按目标总时长等比缩放，没有保护旁白和 TTS 音频。
- 预览阶段看不到字幕时序、版式结构与质量问题。
- 缺少渲染前的自动质量门禁。

## 2. 分步优化处理及效果

### 步骤 1：升级视频 Schema

处理：

- 新增 `schemaVersion: 2`。
- 新增 `CaptionCue`，保存每句字幕的 `startMs`、`endMs` 和强调词。
- 新增 `ScriptBeat` / `VideoBeat`，保存语义节拍、屏幕短文案和视觉动作。
- 新增 `VisualPlan`，保存版式、主视觉、辅助文案、动画预设和可视元素。
- 新增 `audioDurationSeconds`，用于保护真实音频长度。
- 新增 `QualityReport`，保存评分、问题与统计指标。

效果：生成结果从“几段不可执行的描述文字”变成可被 Remotion 直接消费的视觉时间轴。

验证：旧项目 JSON 无需手工迁移；加载时会补齐所有 v2 字段，并保留原有颜色、图片、背景和动画设置。

### 步骤 2：重写大纲与分镜提示词

处理：

- 60 秒视频建议生成 7–10 个短场景，减少 10–15 秒的静态长页。
- 每个场景只表达一个核心观点。
- 中文旁白按每秒约 4 个汉字约束，英文按每秒约 2.5 个词约束。
- 强制生成 2–5 个语义节拍。
- 屏幕文案限制为中文 4–14 字，禁止复制整段旁白。
- 强制生成 2–5 个可视元素。
- 强制在六种版式间变化，避免连续重复。
- 视觉动作必须描述高亮、连线、数值增长或步骤推进等语义变化。

效果：后续新生成的视频会获得更短的镜头、更明确的信息层级和更高的视觉密度。

验证：API 解析器已经支持并规范化 `beats` 与 `visualPlan`；缺失字段时确定性回退，不依赖模型完全遵守格式。

### 步骤 3：逐句字幕与字幕时序

处理：

- 按句号、问号、感叹号、分号拆句。
- 长句继续按逗号或最大行宽拆分。
- 中文单条字幕控制在约 22 个字符以内。
- 根据句子朗读权重分配显示时长。
- 每次只显示当前字幕，并在 4–6 帧内淡入淡出。
- 数字、百分比和引号内关键词自动使用强调色。

效果：字幕从整段常驻变为一句一句出现，观看者无需一次阅读整段文字。

验证：单元测试确认长旁白会拆成至少 3 条字幕；所有 cue 顺序排列且时间不重叠，最后一条不会超过场景结尾。

### 步骤 4：正文与字幕安全区分离

处理：

- 主内容固定在画面上方约 6%–78% 区域。
- 字幕固定在画面底部独立区域。
- 横屏字幕最大宽度约 78%，竖屏约 94%。
- 字幕背景只包裹当前句子，不再使用覆盖整屏宽度的长条。
- 16:9、9:16、1:1 使用不同的安全边距和字号比例。

效果：图文标题、卡片和字幕在结构上不可能占用同一布局区域，消除截图中的直接遮挡。

验证：已分别渲染 16:9、9:16 和 1:1 验证帧；三个画幅中字幕均位于内容区下方，无相交或裁切。

### 步骤 5：实现六种可执行视觉版式

处理：

1. `hero`：主视觉、短副标题和信息标签。
2. `split`：左侧核心解释，右侧辅助信息或图片。
3. `cards`：2–4 张信息卡分批出现。
4. `timeline`：进度线和步骤节点同步推进。
5. `comparison`：Before / After 或双栏观点对比。
6. `diagram`：中心概念和环绕节点关系图。

同时加入：

- 数字、步骤、对比、概念和引用五种矢量图形。
- 没有图片时自动使用卡片、图标、关系图等原生视觉，不再退化为空白页。
- 根据标题长度自动缩小字号。
- 卡片内容较短时不再被网格强制拉高。

效果：`visual` 不再只是编辑器里的备注；即使没有外部图片，也能形成完整的信息画面。

验证：六种版式均已通过 Remotion 实际渲染，验证图片位于 `artifacts/validation/`。

### 步骤 6：增加元素级动画和持续运动

处理：

- 场景入场使用弹簧动画。
- 卡片、节点和面板按场景进度或语义节拍分批出现。
- 当前信息元素获得边框、阴影和位置高亮。
- 时间轴进度会持续推进。
- 关系图轨道会缓慢旋转。
- 背景网格、光团持续做低幅度位移。
- 场景结尾增加快速淡出，减少硬切。

效果：动画不再只发生在前 0.7 秒；一个场景内会持续发生与语义相关的视觉变化。

验证：同一 `cards` 场景分别渲染 15%、35%、60% 三个时间点，三个文件 SHA-256 均不同，且逐帧检查可见信息卡分批进入；脚本输出 `motionFramesDistinct: true`。

### 步骤 7：旁白、字幕、TTS 与时长校准

处理：

- 中文按约 4.6 字/秒、英文按约 2.7 词/秒估算朗读时间。
- 场景最小时长取旁白时间、字幕展示时间、动画最低时间、真实音频时间的最大值。
- 目标总时长足够时，按原场景权重分配余量。
- 目标总时长不足时自动延长成片，不再截断旁白。
- 浏览器生成 TTS 后立即读取音频 metadata，将真实音频时长写入场景。
- 修改旁白时自动清除已失效的旧音频时长。

效果：解决“很长的旁白被压进 6 秒”和 TTS 尾部被切断的问题。

验证：单元测试使用 12.4 秒音频模拟数据，场景被保护到至少 12.75 秒；目标总时长不足时允许成片自动延长。

### 步骤 8：升级文稿与预览编辑器

处理：

- 文稿页显示基于字数计算的建议最小时长。
- 增加高级视觉编排，可调整版式、主视觉短句和视觉节拍。
- 预览页可以直接切换六种版式。
- 修改旁白后自动重新分句和重新计时。
- 预览页显示每条字幕及开始时间。
- 预览页显示质量分数、节拍数量、字幕数量、版式数量和平均视觉元素数量。
- TTS 生成后显示经过真实音频校准的时长。

效果：用户能看见并调整过去隐藏在 JSON 中的关键视觉决策。

验证：TypeScript 严格检查和 Next.js 生产构建均通过。

### 步骤 9：增加自动质量门禁

处理：

- 检查中长视频场景数量是否过少。
- 检查可视元素是否少于 2 个。
- 检查是否缺少语义节拍。
- 检查单一节拍是否静止过久。
- 检查字幕是否过长。
- 检查旁白预计时间是否超过场景时长。
- 检查标题是否过长。
- 检查连续三个场景是否使用相同版式。
- 错误级问题会阻止导出；警告允许导出但在预览中明确显示。

效果：明显的字幕、时长和布局问题不会未经提示直接进入 MP4 渲染。

验证：标准验证 Schema 得分为 100/100，错误与警告均为 0。
