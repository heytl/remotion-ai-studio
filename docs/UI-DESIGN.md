# Motion Lab UI 设计规范

> 本文记录 2026-08 的 UI 重构成果，是后续界面设计与实现的共同基线。实现以 [Tailwind CSS](https://tailwindcss.com/)、shadcn 风格组件与 Radix 原语为基础。

## 1. 设计定位

Motion Lab 是一个从创意到成片的 AI 视频制作工作台。界面采用 **Cinematic AI Production Console（电影感 AI 制作台）**：深色、克制、专业，强调创作流的连续性，而不是把页面做成普通表单后台。

- **氛围**：OLED 深色基底，靛蓝为主要行动色，青色用于信号与技术感提示。
- **层级**：大标题与短说明建立页面目标；内容使用半透明面板分组；主操作只保留一个高亮入口。
- **信息密度**：编辑工作台可以紧凑，首页与设置页保留足够的呼吸空间。
- **表达原则**：通过间距、字号、边界与状态文案传达优先级；不要只依赖颜色传达状态。

## 2. 设计令牌

所有语义色均定义在 `app/globals.css`，通过 Tailwind 的 `background`、`foreground`、`primary`、`muted`、`border` 等语义类使用。新页面或组件不应重新硬编码基础色。

| Token | 用途 | 当前值（HSL） |
| --- | --- | --- |
| `--background` | 页面 OLED 深色背景 | `222 44% 5%` |
| `--foreground` | 主文字 | `216 45% 98%` |
| `--card` | 卡片与面板表面 | `222 44% 10%` |
| `--primary` | 主操作、当前步骤、品牌渐变基色 | `233 100% 72%` |
| `--ring` | 键盘焦点、青色技术强调 | `186 79% 53%` |
| `--secondary` / `--accent` | 次级容器、悬停表面 | 深蓝灰 |
| `--muted-foreground` | 辅助文案与次级标签 | `216 20% 66%` |
| `--destructive` | 删除、失败等风险操作 | `0 72% 51%` |
| `--radius` | 大组件圆角基础 | `0.9rem` |

### 背景与效果

- 页面背景由两层低透明度径向光晕叠加在深色底上，避免使用高饱和大面积渐变。
- `.glass-panel` 用于主要创作面板：深色半透明渐变与 `backdrop-filter`，保持文字对比。
- `.studio-grid` 仅用于需要“制作台/信号面板”质感的局部区域，网格线应保持极低对比度。
- `shadow-panel` 用于浮起的大面板，`shadow-glow` 仅用于品牌与主行动，避免泛滥。

## 3. 排版与间距

### 字体

使用系统优先的无衬线字体栈：`Inter`、系统 UI 字体、`PingFang SC`、`Microsoft YaHei`。中文正文不使用过紧字距；数字、时间码和任务 ID 可使用 `font-mono`，避免数字跳动。

### 字号层级

| 场景 | 建议类 / 尺寸 |
| --- | --- |
| 页面主标题 | `text-2xl sm:text-3xl`；首页 Hero 可至 `text-4xl sm:text-5xl lg:text-[56px]` |
| 卡片标题 | `text-base font-semibold` |
| 正文与说明 | `text-sm leading-6` |
| 标签、眉题、状态 | `text-[10px]` 或 `text-[11px]` + 大写字距 |
| 辅助信息 | `text-xs`，使用 `text-muted-foreground` |

### 间距节奏

以 4px / 8px 为基准建立节奏。优先使用现有 Tailwind 阶梯：

- 紧密元素（图标与标签、同行控件）：`gap-2` / `gap-3`
- 表单字段与同级卡片内容：`gap-4` / `space-y-4` / `space-y-5`
- 页面区块：`mt-6`、`mt-8`、`mt-9`、`mt-10`
- 卡片内边距：小屏 `p-5`，`sm` 及以上 `p-6`；带标题分隔线的内容区须显式设置 `pt-5 sm:pt-6`，不可继承 `CardContent` 的默认 `pt-0`。

## 4. 基础组件约定

基础组件位于 `components/ui/`；业务页面只组合这些组件与语义化容器，避免复制按钮、输入框与卡片的基础样式。

| 组件 | 使用约定 |
| --- | --- |
| `Button` | 默认样式只用于页面的唯一主操作；`outline` 用于次要操作，`ghost` 用于低强调导航或返回。新增固定风格时扩展 CVA variant，不在调用处堆叠条件颜色。 |
| `Card` | 用于一级信息分组；`CardHeader` 可通过底边框分隔，`CardContent` 默认无顶部内边距，分隔后的内容需要手动补回。 |
| `Field` + `Label` | 所有表单项必须有可见标签；复杂字段可加 `hint`。不要仅以 placeholder 充当标签。 |
| `Input` / `Textarea` / `NativeSelect` | 输入高度不低于 44px，禁用状态应保留清晰的可读性与不可操作语义。 |
| `Switch` | 使用 Radix 原语，必须有可访问名称。状态除颜色外，应提供如“已启用 / 未启用”的文字。 |
| `Badge` / `Progress` | 表示任务状态、数量或进度；不作为普通按钮或无意义装饰。 |
| `ErrorBanner` / `EmptyState` | API 失败、无项目、无渲染任务等场景使用统一反馈，不留空白区域。 |

图标统一使用 `@phosphor-icons/react`。图标仅为相邻文字装饰时添加 `aria-hidden="true"`；独立图标按钮必须提供 `aria-label`。

## 5. 页面与信息架构

### 全局工作区壳层

- **桌面（`lg` 起）**：左侧 230px 固定工作区导航，顶部状态条，内容区最大宽度 1320px。
- **移动端**：隐藏侧边栏，在顶部保留品牌、创作空间和系统设置的图标入口。
- 每个页面通过 `main#main-content` 接收跳转链接，保持键盘访问路径清晰。

### 首页：创作入口

- Hero 先传达“把想法变成影片”的价值，再进入主题、画幅、时长、风格与语言配置。
- 右侧轨道/光球视觉只承担品牌氛围，不承载业务信息。
- 最近项目采用可继续的项目卡；底部用三项摘要补充工作区规模与导出能力。

### 系统设置：服务配置

- “大模型服务”和“TTS 语音合成”分别是独立卡片；前者偏配置与测试，后者围绕启用状态渐进展示。
- 卡片标题区与内容区若有分隔线，内容区保留 `20px / 24px` 顶部空白，避免首项控件贴线。
- API Key 使用密码输入；环境变量优先级以说明卡提示，不与可编辑设置混为一组。

### 项目工作台：五阶段创作流

1. **需求**：定义主题、受众、时长、画幅与语言。
2. **大纲**：规划叙事章节、要点和时长占比。
3. **文稿**：编辑分镜、旁白、视觉描述与配音。
4. **预览**：播放器、场景轨道和 Inspector 同屏协作。
5. **导出**：展示视频摘要、渲染主操作与任务历史。

桌面使用左侧纵向步骤导航；移动端采用可横向滚动的步骤条，滚动必须限制在导航自身，不能撑宽页面。已完成步骤使用勾选图标和文字层级共同表达状态。

## 6. 响应式规则

- 页面基线宽度为 320px；正文和输入框在手机端不应小于 16px 可读尺寸。
- 内容容器必须使用 `min-w-0`、`minmax(0, 1fr)` 等约束避免网格的最小内容宽度导致横向溢出。
- 表单先单列，`sm` 及以上再切双列；设置页的双卡布局在 `xl` 才改为主栏 + 360px 侧栏。
- 项目预览的播放器、场景轨道和 Inspector 在小屏顺序纵向排列；不要用固定宽度挤压内容。
- 每次修改布局至少检查 390px 手机宽度与常规桌面宽度，`documentElement.scrollWidth` 应不大于 `clientWidth`。

## 7. 交互、状态与可访问性

- 键盘焦点使用 `ring` 语义色，禁止移除 `focus-visible` 样式。
- 可点击组件保留 44px 左右的最小触控高度；图标按钮须有明确标签。
- 主操作的加载态使用按钮内 Spinner，并在请求期间禁用重复提交。
- 错误使用近场 `ErrorBanner` 或字段提示，状态更新以文字配合颜色与图标。
- 全局尊重 `prefers-reduced-motion`：动画与过渡应静止或缩短，不用运动来表达唯一信息。
- 页面不依赖 hover 才能完成操作；移动端导航和步骤切换均可点击。

## 8. 后续实现清单

新增或调整界面时，请按以下顺序执行：

1. 先复用语义 token 和现有 `components/ui`，确定信息层级与唯一主操作。
2. 为新组件补齐默认、悬停、焦点、禁用、加载或空状态；需要固定组合风格时通过 CVA variant 扩展。
3. 在 390px 与桌面宽度检查布局、横向溢出、触控目标与文字换行。
4. 使用 `npm run build` 完成类型与生产构建验证。
