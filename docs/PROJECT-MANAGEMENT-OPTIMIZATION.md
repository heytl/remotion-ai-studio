# 项目管理优化记录

## 目标

解决三个直接影响使用的问题：项目缺少删除入口、列表无法判断制作状态、再次进入项目总是回到第一步。

## 逐步优化处理

### 1. 建立统一项目状态模型

- 新增七种状态：草稿、大纲完成、文稿完成、可预览、渲染中、已完成、渲染失败。
- 状态不依赖容易过期的手工字段，而是由大纲、文稿、Schema 和最新渲染任务实时推导。
- 同时计算五步完成数和百分比；渲染中会把真实渲染进度映射到最后 20%。

效果：项目列表可以准确表达项目当前处于哪一阶段，渲染失败也不再伪装成“可继续”。

### 2. 兼容已有项目

- 新增 `workflow.currentStep` 和 `workflow.lastVisitedAt`。
- 旧项目没有 `workflow` 时，会按已有数据自动推断恢复位置：有大纲回到大纲、有文稿回到文稿、有预览回到预览、有渲染记录回到导出。
- 读取旧 Schema 时继续执行现有的 Schema v2 归一化，不要求手工迁移 JSON 文件。

效果：现有项目无需删除或重建，第一次打开即可获得合理状态和恢复位置。

### 3. 持久化最后停留步骤

- 点击侧边步骤、下一步或上一步时，立即保存新的工作流位置。
- URL 同步写入可读步骤参数，例如 `?step=preview`；直接打开带步骤的地址也会恢复并保存该位置。
- 编辑器标题区显示“第 N/5 步”，侧边栏继续保留当前步骤高亮。

效果：返回首页再进入项目时，会直接回到用户真正离开的步骤，而不是固定回到需求页。

### 4. 升级项目列表为管理视图

- 每个项目卡片显示状态徽标、五步进度、百分比、更新时间和“继续到某步骤”。
- 项目入口带上已保存的步骤地址。
- 删除按钮与进入项目的链接分离，避免误触和无效的嵌套交互。

效果：无需打开项目即可判断工作量和下一步动作，也能从列表直接续作或管理项目。

### 5. 实现安全删除闭环

- 删除前显示明确二次确认，说明项目内容、渲染记录和导出视频都会被永久删除。
- 删除过程中按钮进入加载状态，成功后立即从列表移除并显示成功消息，失败时显示具体错误。
- 服务端删除项目 JSON、所属渲染任务 JSON 和输出目录内的 MP4；路径经过项目 ID 和目录边界校验。
- 渲染中或排队中的项目返回冲突提示，禁止删除，避免运行任务生成孤立文件。
- 删除不存在的项目返回 404，不再静默报告成功。

效果：删除功能可见、可理解、可验证，同时降低误删和孤立数据风险。
